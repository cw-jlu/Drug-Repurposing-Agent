# Trace policy

Every new Agent, LLM, evaluation, LUAD packaging, and expression-workflow run writes a unique append-only JSONL trace. Events are flushed to disk immediately, so completed steps remain available if a later step fails. The output report includes `trace_file`; an LLM-backed run also links its provider-call trace as `provider_trace_file` or in planner metadata. Agent/evaluation traces record input context, available tools, chosen tool and arguments, validation outcome, errors, latency, and provider usage when reported. Provider traces contain the model-visible request and provider-visible response after redaction. These are observed inputs and outputs, **not** a record of inaccessible internal reasoning.

The official B2/component runner wrappers and comparison scripts also trace parameters, pinned upstream revision, staged-input or result hashes, subprocess start/completion, comparison decisions, and failures. The upstream runner itself is external code; these wrapper traces do not claim to contain every inner training-fold event. Its seed and result files remain the detailed run evidence. New comparison runs default to ignored `artifacts/reports/` so the frozen `benchmark/results/` files are not overwritten accidentally.

Default provider traces go to `artifacts/traces/` (override with `DRUG_AGENT_TRACE_DIR`). Run-specific traces live in the output directory's `traces/` subdirectory. `artifacts/` is Git-ignored. Traces may contain research prompts, model outputs, or biomedical content even after credential redaction; review them before sharing or committing. Credential fields, configured API-key values, common bearer/key patterns, and internal-reasoning fields are removed. Do not place secrets in filenames or unusual free-text formats.

The frozen historical planner-v3 and benchmark results predate this policy. Their existing records can be examined, but raw provider interactions or hidden reasoning cannot be recreated retroactively. Do not silently replace the frozen v1 method-selector result: new selector runs default to `artifacts/reports/component_llm_selector.json`.

For a newly traced Planner v3 run, `python -m evals.grade_planner_traces --report artifacts/reports/planner_v3_rule_trace_regression.json --cases configs/planner_eval_v3_holdout.json --output artifacts/reports/planner_v3_rule_trace_grade.json` checks case-file integrity, per-case inputs, tool and argument consistency, safety boundaries, and provider-trace presence where applicable. A trace grade is an audit of recorded behavior, not proof of hidden reasoning or biomedical prediction quality. The historical 98/100 DeepSeek v3 report lacks raw provider traces and is deliberately not trace-gradeable; it must not be represented as 98/100 trace-verified.

Prospective method-selection traces and their label-blind input contract are described in `method_selection_partition_v2.md`. The five partition inputs were committed before any new model choices or partition outcomes. Model calls and official runs remain pending, so the protocol has no measured selector benefit yet.
