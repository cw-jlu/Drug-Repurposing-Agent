# Trace policy

Every new Agent, LLM, evaluation, LUAD packaging, and expression-workflow run writes a unique append-only JSONL trace. Events are flushed to disk immediately, so completed steps remain available if a later step fails. New events carry sequence numbers and a SHA-256 previous-event chain; `verify_trace_chain` detects later edits, omissions or reordering within a saved file. A file could still be replaced wholesale unless its final digest is preserved separately, so saved reports include trace hashes or receipts when practical. The output report includes `trace_file`; an LLM-backed run also links its provider-call trace as `provider_trace_file` or in planner metadata. Agent/evaluation traces record input context, available tools, chosen tool and arguments, validation outcome, errors, latency, and provider usage when reported. Provider traces contain the model-visible request and provider-visible response after redaction. These are observed inputs and outputs, **not** a record of inaccessible internal reasoning.

The official B2/component runner wrappers and comparison scripts also trace parameters, pinned upstream revision, staged-input or result hashes, subprocess start/completion, comparison decisions, and failures. The upstream runner itself is external code; these wrapper traces do not claim to contain every inner training-fold event. Its seed and result files remain the detailed run evidence. New comparison runs default to ignored `artifacts/reports/` so the frozen `benchmark/results/` files are not overwritten accidentally.

Default provider traces go to `artifacts/traces/` (override with `DRUG_AGENT_TRACE_DIR`). Run-specific traces live in the output directory's `traces/` subdirectory. `artifacts/` is Git-ignored. Traces may contain research prompts, model outputs, or biomedical content even after credential redaction; review them before sharing or committing. Credential fields, configured API-key values, common bearer/key patterns, and internal-reasoning fields are removed. Do not place secrets in filenames or unusual free-text formats.

The frozen historical planner-v3 and benchmark results predate this policy. Their existing records can be examined, but raw provider interactions or hidden reasoning cannot be recreated retroactively. Do not silently replace the frozen v1 method-selector result: new selector runs default to `artifacts/reports/component_llm_selector.json`.

The committed `benchmark/results/planner_v3_rule_chained_regression.json`, its linked JSONL trace, and `benchmark/results/planner_v3_rule_chained_trace_grade.json` preserve a reproducible rule-planner regression snapshot. `python -m evals.grade_planner_traces --report benchmark/results/planner_v3_rule_chained_regression.json --cases configs/planner_eval_v3_holdout.json --output artifacts/reports/planner_v3_rule_regrade.json` rechecks case-file and chain integrity, event order, per-case inputs, report-to-trace consistency, tool and argument validity, and safety boundaries. For new DeepSeek runs it also checks that each provider-visible request contains the evaluated question/context and that the recorded provider tool selection reconciles with the final call; file existence alone is insufficient. A trace grade is an audit of recorded behavior, not proof of hidden reasoning or biomedical prediction quality. The historical 98/100 DeepSeek v3 report lacks raw provider traces and is deliberately not trace-gradeable; it must not be represented as 98/100 trace-verified.

Prospective method-selection traces and their label-blind input contract are described in `method_selection_partition_v2.md`. `evals/grade_method_selection_traces.py` checks every provider-visible blind request and response against the frozen choice, including provider-trace SHA-256; the outcome scorer requires a full pass. The five partition inputs were committed before any new model choices or partition outcomes. Model calls and official runs remain pending, so the protocol has no measured v2 selector benefit yet. `evals/audit_historical_selector_v1.py` separately produces a trace-backed, paired retrospective analysis from already committed 100-run files; it is not a new holdout.
