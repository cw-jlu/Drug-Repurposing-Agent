# Agent 端到端稳定性（v1）

2026-10-01。对应项目计划 10.7 节的验收门槛：端到端完成率 ≥ 90%，固定配置下排名 Spearman ≥ 0.95。任务为 Strict 模式下的 TRANSCRIPT 全流程排名；5 种固定说法（中英文、不同措辞）× 每种 2 次，规则规划器与 DeepSeek `deepseek-flash` 规划器各 10 次。说法在运行前写入脚本，运行后未修改。脚本：`python -m evals.agent_repeatability`；结果：`benchmark/results/agent_repeatability_v1.json`；每次运行的 Agent trace 位于被忽略的 `artifacts/agent_repeatability/`。

| 指标 | 规则规划器 | DeepSeek 规划器 |
|---|---:|---:|
| 完成 / 运行 | 8/10 | 10/10 |
| 完成率门槛 ≥ 0.90 | 未通过 | 通过 |
| 已完成运行中不同的工具计划数 | 1 | 1 |
| 不同的 RRF 输出哈希数 | 1 | 1 |
| 与首次运行排名的最小 Spearman | 1.000 | 1.000 |
| Spearman 门槛 ≥ 0.95 | 通过 | 通过 |
| 单次耗时 P50 / P95（秒） | 2.31 / 2.48 | 3.25 / 3.71 |
| 模型 token（提示 / 完成，合计） | 0 / 0 | 5,600 / 282 |

**结论**

- 一旦工具计划确定，计算完全可复现：所有完成的运行输出同一个 RRF 矩阵（哈希一致，Spearman = 1.0），因为排序由确定性工具完成，LLM 不接触数值。
- 差异只出现在“理解请求”这一步：规则规划器无法识别第 5 种说法（“请对 TRANSCRIPT 数据运行表达反转并输出排名矩阵”），两次都安全地转人工审核，完成率 0.8，未达 0.9 门槛；DeepSeek 10/10 完成，计划始终为同一个工具调用。
- 失败方式是保守的（转人工），没有执行错误工具。这与 100 例冻结 holdout 中规则 90/100、DeepSeek 98/100 的差距方向一致。
- 局限：只测了一种任务、5 种说法、每种 2 次；DeepSeek 在 temperature 0 下的稳定性不代表更换模型版本后的表现。
