\section{Agent
v2：多步规划、依赖校验与有限重规划}\label{agent-v2ux591aux6b65ux89c4ux5212ux4f9dux8d56ux6821ux9a8cux4e0eux6709ux9650ux91cdux89c4ux5212}

2026-10-02。v1 的规划器只从 3 个工具里选 1 个（100 例冻结测试中 75
例的标准答案是安全拒绝）。v2
让大模型把一句请求拆成有序的多步计划，代码负责校验并执行，失败时把观察反馈给大模型重新规划。v1
及其结果保持不变。代码：\texttt{src/\allowbreak{}drug\_\allowbreak{}repurposing\_\allowbreak{}agent/\allowbreak{}agent\_\allowbreak{}v2.\allowbreak{}py}（规划、校验、执行循环）、\texttt{src/\allowbreak{}drug\_\allowbreak{}repurposing\_\allowbreak{}agent/\allowbreak{}luad\_\allowbreak{}tools\_\allowbreak{}v2.\allowbreak{}py}（真实工具）、\texttt{scripts/\allowbreak{}run\_\allowbreak{}agent\_\allowbreak{}v2.\allowbreak{}py}（命令行）。

\subsection{设计}\label{ux8bbeux8ba1}

\begin{itemize}
\tightlist
\item
  \textbf{9 个工具}（v2.1 起加上 \texttt{fetch\_\allowbreak{}geo\_\allowbreak{}series} 共 10
  个，见下文），每个都声明需要的外部输入、依赖的前序产物与自己的产物：\texttt{qc\_\allowbreak{}disease\_\allowbreak{}cohort}
  → \texttt{differential\_\allowbreak{}expression} → \texttt{pathway\_\allowbreak{}enrichment} /
  \texttt{rank\_\allowbreak{}candidates} → \texttt{audit\_\allowbreak{}candidates} /
  \texttt{review\_\allowbreak{}literature} → \texttt{build\_\allowbreak{}report}；另有基准用的
  \texttt{rank\_\allowbreak{}transcriptome} 和安全停止的
  \texttt{manual\_\allowbreak{}review}。LUAD 工具只允许在 Open 模式使用。
\item
  \textbf{大模型一次提交完整计划}（\texttt{submit\_\allowbreak{}plan}
  函数调用，含任务、理由和步骤列表）。
\item
  \textbf{代码校验每个计划}：工具在白名单内且允许当前模式；每一步的依赖由更早的步骤或已有产物满足；所需外部输入真实存在；\texttt{manual\_\allowbreak{}review}
  只能是最后一步。不合法的计划不会执行。
\item
  \textbf{观察---重规划循环}：计划不合法或某一步失败时，把失败原因和已有产物反馈给大模型重新规划；已完成的步骤不会重跑；最多
  3 轮，用尽后转人工。
\end{itemize}

\subsection{什么由大模型决定，什么是固定的}\label{ux4ec0ux4e48ux7531ux5927ux6a21ux578bux51b3ux5b9aux4ec0ux4e48ux662fux56faux5b9aux7684}

\textbf{由大模型决定（随请求变化）}：调用哪些工具、按什么顺序、做到哪一步停下、失败后补哪几步。冻结
40 例中，DeepSeek 第一轮给出了 9 种不同的计划：完整 7 步流程 21
例，其余包括只做质控、质控 → 差异表达、质控 → 差异表达 →
通路、不查文献的 5
步流程、只做基准排名、直接转人工等。缺少药物签名时，它先完成质控、差异表达和通路分析，再转人工；排名失败后的第
2 轮只规划剩余步骤。

\textbf{固定的（由代码决定）}：

\begin{itemize}
\tightlist
\item
  每个工具内部的算法与参数：配对检验、FDR \textless{} 0.05 且
  \textbar log2FC\textbar{} ≥ 1 的签名阈值、反转打分与 RRF 融合（k =
  60）、Hallmark/KEGG 富集方法都写在代码里；
\item
  工具之间的依赖关系，以及每个模式允许哪些工具；
\item
  工具集合本身：只有 9 个，大模型不能新增工具或执行自己写的代码。
\end{itemize}

计划格式中每一步虽然有 \texttt{arguments}
字段，但真实后端（\texttt{luad\_\allowbreak{}tools\_\allowbreak{}v2.\allowbreak{}py}）\textbf{不读取它}，所以大模型无法改动阈值或方法。它也看不到中间的科学结果（排名、通路），只看到哪些产物已完成以及失败原因。

\textbf{为什么这样设计}：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  阈值会改变结论。阈值敏感性分析（\texttt{docs/\allowbreak{}luad\_\allowbreak{}threshold\_\allowbreak{}sensitivity.\allowbreak{}md}）显示，把
  \textbar log2FC\textbar{} 从 1 放宽到 0.58，Top-10 与冻结结果只重合
  3--4
  个。如果让大模型在看到结果后挑阈值，就等于事后调参，结果也不可复现。
\item
  让大模型挑方法并没有带来更好的结果：五分区方法选择实验中，大模型所选方法比固定
  B2 平均低 0.11
  NS-AUC（\texttt{docs/\allowbreak{}method\_\allowbreak{}selection\_\allowbreak{}partition\_\allowbreak{}v2.\allowbreak{}md}）。
\item
  固定参数才能让``同一请求 → 同一排名''成立；Agent
  可重复性实验中所有完成的运行输出同一排名矩阵（\texttt{docs/\allowbreak{}agent\_\allowbreak{}repeatability.\allowbreak{}md}）。
\end{enumerate}

一句话：\textbf{固定的是``积木''，大模型决定``怎么拼''。}
若以后要开放参数，只应开放不改变科学结论的少量选项（如报告中展示的
Top-K），由代码限定取值范围，并在新的冻结用例集上重新评估。

\subsection{v2.1：疾病登记表与自动下载（2026-10-03）}\label{v21ux75beux75c5ux767bux8bb0ux8868ux4e0eux81eaux52a8ux4e0bux8f7d2026-10-03}

\textbf{能力边界：只支持登记表中的疾病，不支持任意疾病。}
\texttt{configs/\allowbreak{}disease\_\allowbreak{}registry\_\allowbreak{}v1.\allowbreak{}json}
目前只登记了肺腺癌（GSE32863，配对 57 对，药物端用 LINCS
A549）。每个条目固定 GEO 编号、文件 URL 与
SHA-256、样本配对规则、预期样本数、取值尺度和药物细胞系。

\begin{itemize}
\tightlist
\item
  \textbf{疾病识别由代码完成}：\texttt{geo\_\allowbreak{}cohort.\allowbreak{}resolve\_\allowbreak{}disease}
  只按登记的别名匹配，不做猜测。``肺癌''被有意排除在别名之外，因为它还包括鳞癌和小细胞癌，而这个队列不代表它们。未登记的疾病拿不到任何疾病输入，Agent
  转人工并说明原因。
\item
  \textbf{新工具
  \texttt{fetch\_\allowbreak{}geo\_\allowbreak{}series}}：只有请求中点名了登记疾病时才提供给规划器。它从
  NCBI 下载数据并核对哈希，哈希不一致就拒绝。
\item
  \textbf{质控和差异表达始终从原始 series matrix 重算}，不读
  \texttt{data/\allowbreak{}processed/\allowbreak{}} 下的缓存。在 GSE32863 上，新代码约 1
  秒重算出与冻结 \texttt{luad\_\allowbreak{}deg\_\allowbreak{}all.\allowbreak{}tsv} 逐字节一致的签名（512
  个上调 / 749 个下调）。
\item
  排名使用登记的细胞系；没有预设参考药的疾病不计算恢复统计。文献审阅当时只支持肺腺癌（v2.2
  起已可配置，见下节）。
\end{itemize}

\textbf{真实运行}（\texttt{benchmark/\allowbreak{}results/\allowbreak{}agent\_\allowbreak{}v2\_\allowbreak{}registry\_\allowbreak{}runs.\allowbreak{}json}）：先把
GSE32863 原始文件移走，规则和 DeepSeek 规划器都规划出``下载 → 质控 →
差异表达 → \ldots\ldots{} →
报告''。下载文件的哈希与登记表一致，签名逐字节复现，Top-10 不变，全程约
28 秒。请求乳腺癌时（当时乳腺癌尚未登记），DeepSeek 只提交了
\texttt{manual\_\allowbreak{}review}，并说明目前只登记了 LUAD。

\textbf{冻结 40 例在新版本上重跑}（用例文件未改动）：规则规划器两次都是
30/40。DeepSeek 在下载工具始终可见时为 37/40：有 10
例先规划了无法执行的下载步骤，被校验拒绝后重新规划才恢复。改为``只在登记疾病时提供下载工具''后为
38/40，下载工具一次也没被规划。原始结果 36/40、37/40、38/40
之间的差别属于逐次运行的波动，不能算作改进。结果文件为
\texttt{planner\_\allowbreak{}eval\_\allowbreak{}multistep\_\allowbreak{}v1\_\allowbreak{}1.\allowbreak{}json} 和
\texttt{planner\_\allowbreak{}eval\_\allowbreak{}multistep\_\allowbreak{}v1\_\allowbreak{}2.\allowbreak{}json}，原 v1 结果保留不动。

\textbf{第二个疾病的可行性}（\texttt{benchmark/\allowbreak{}results/\allowbreak{}disease\_\allowbreak{}feasibility\_\allowbreak{}gse15852.\allowbreak{}json}，当时未登记，v2.2
已登记）：用同一套代码对乳腺癌 GSE15852 试跑，药物端用 MCF7。

\begin{itemize}
\tightlist
\item
  结果：43 对样本全部配对；程序自动识别出原始值未取对数并做了 log2
  转换；得到 115 个上调、193 个下调；Hallmark 上调为 E2F、G2-M
  和雌激素反应。本地 LINCS 文件已包含 MCF7 的 6,231 个化合物，排名只用 6
  秒。
\item
  结论：\textbf{技术上可行}，加入登记表只需新增一个 JSON 条目。
\item
  尚不能作为结论：签名落在 landmark 基因上只有 19 个上调、22
  个下调；Top-10 是
  CDK、PI3K、拓扑异构酶等通用抗增殖药；乳腺癌没有预设参考药；文献审阅也需要先改成可参数化的检索式。
\end{itemize}

\subsection{v2.2：登记乳腺癌，文献审阅可配置（2026-10-03）}\label{v22ux767bux8bb0ux4e73ux817aux764cux6587ux732eux5ba1ux9605ux53efux914dux7f6e2026-10-03}

\textbf{登记表现在有两个疾病}：

\begin{itemize}
\tightlist
\item
  肺腺癌：GSE32863，药物端 A549，有冻结的文献审阅；
\item
  乳腺癌：GSE15852（43 对），药物端 MCF7，文献审阅只能实时运行。
\end{itemize}

MCF7 是雌激素受体阳性细胞系，所以药物端不代表 HER2
阳性或三阴性乳腺癌。``肺癌''仍不是肺腺癌的别名。

\textbf{文献审阅可配置}（\texttt{multi\_\allowbreak{}agent\_\allowbreak{}review.\allowbreak{}ReviewConfig}）：PubMed
检索的疾病过滤式、给各 Agent 看的疾病名、系统提示词、批评 Agent
的问题标签和可选的药物类别反证检索，都从登记表的 \texttt{literature}
配置读取。

\begin{itemize}
\tightlist
\item
  肺腺癌使用 \texttt{luad\_\allowbreak{}v1}
  预设，提示词、检索式和输出格式与冻结审阅逐字相同，有测试锁定，冻结结果仍可复现。
\item
  其他疾病使用中性模板：不提糖皮质激素，也不做类别反证检索。
\item
  没有身份审计记录的候选按 LINCS 名称检索，并标记为``未做身份审计''。
\end{itemize}

\subsection{局限}\label{ux5c40ux9650}

\begin{itemize}
\tightlist
\item
  模拟后端只检验规划与恢复逻辑，不检验科学结果。
\item
  只能分析登记表中的疾病（目前是肺腺癌和乳腺癌）；乳腺癌没有冻结的文献审阅，也没有候选身份审计；不能自动检索
  GEO
  来为任意疾病挑选数据集，因为分组规则和数据质量都需要人工核对后才能登记。
\item
  文献工具在 Top-10 与冻结结果一致时复用冻结的多 Agent
  审阅，避免意外的付费调用。
\item
  用例由作者编写，每个规划器只运行一次；越权类的结果说明，安全仍需依靠代码层的白名单与依赖校验，而不能只靠大模型的判断。
\end{itemize}
